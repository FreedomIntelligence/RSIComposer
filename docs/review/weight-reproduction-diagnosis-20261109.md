# SEAL / TTRL 未测得收益的归因审查

日期：2026-11-09。审查对象是两次冻结的 v1 实验，框架诊断基线为
`b5a0e899364b05f03d07e3ff6c52699f5228d84d`。
本报告补充[原架构检查](weight-evolution-architecture-20261109.md)，
不改写原始实验、奖励或已发布 checkpoint。

## 结论与责任边界

**首先是我们的复现方案和实现对齐问题；目前没有证据判定论文结论有问题。**
先前实验完成了注册和真实训练闭环，但修改了数据规模、优化、奖励和评测协议，
尚未完成同设置复现。把结果仅概括为“论文收益未复现”，不足以说明这项责任。

- SEAL：已确认内层学习率日程、序列构造等偏差对结果有实质影响。
  8 卡受控实跑显示，同一批冻结 self-edit 上只改变内层优化就能明显改变分数；
  四组条件下外层模型的收益方向也会改变。不能由原始负结果推断方法失效。
- TTRL：官方判分器重算后，最终准确率没有变化；因此最终判分器不是本次平分/掉分的解释。
  但我们没有完成官方全参数后端、采样预算、训练日程及主表评测的对齐。
  现有证据不足以把失败归给论文，也不足以给各偏差分摊因果百分比。
- 小样本的正负变化都不稳定。后验诊断中的正结果也不能升级成论文数值复现。

## 对照源与版本

使用 SEAL [论文 v2，附录 B.2–B.4][seal-paper]，TTRL
[论文 v3，§3.1][ttrl-paper]；原始版本同时核对。
TTRL [v1][ttrl-v1] 使用 greedy 描述主结果，v3 的主表使用采样 pass@1，
不能把两个版本的评测设置混用。两方法都包括 Qwen2.5-7B Base，
因此不能将本次问题简单归结为“用了错误型号的模型”。

上游实现固定为 SEAL `6d9c9f9ee392c6cc618e771f399d436d190f6ca4`、
TTRL `5806e119789132fcb43552beaf2532d7d0447213`。
以下区分论文、该源码版本以及我们的实际运行，不用其中之一替代另外两者。

## SEAL：已经证实的实现侧影响

### 训练和评测设置没有对齐

| 项目 | 论文/上游设置 | 原 v1 实跑 |
| --- | --- | --- |
| 外层每轮训练文档 | 50 | 8 |
| 每文档候选 / 内层重复测量 | 5 / 3 个随机种子 | 2 / 1 |
| 外层有效 batch / LoRA rank | 10 / 64 | 8 / 32 |
| 两轮外层更新 | 按论文 batch、epochs 计算为 20 步 | 4 步 |
| 单文档 self-edit 构造 | 论文按行拆分 | 按 `---` 拆分；这些候选实际均成为整段 + 原文 |
| 内层优化日程 | [上游 Trainer][seal-inner] 默认 linear | 独立 AdamW 常数学习率 |
| 验证集 / 判分 | 200 文档、974 题，GPT-4.1 语义正确性 | 8 文档、45 题，词面 EM/F1 |

原有 conformance 对照只验证了上游 `build_train_sequences` 的
`split_newlines=False` 默认分支，不覆盖论文要求的按行分支，
也没有验证 Trainer、完整评测或奖励的等价性。
32 个训练候选实际各只有 2 条序列、20 步；按上游的按行选项重构后为 4–11 条序列。

奖励口径不是只影响最后显示的一个数：我们用 F1 选择 self-edit，
论文用适配后的语义正确率选择。长但正确的回答可能被词面 F1 惩罚，
这会改变外层学习的候选。当前没有完整 GPT 判分对照，不能声称候选语义排序等价。

### 8 卡冻结 self-edit 对照

新增外部注册的固定日程 controller + Lab，经同一 `rsisys run --config --plugin` 入口执行。
每组都使用已有 8 篇验证文档/45 个问题、各模型当时保存的同一组 self-edit、
同一随机种子与样本顺序。只改变内层序列拆分和学习率日程；没有重新生成或选择候选，
没有外层更新。标签只在 worker 返回预测后用于评测。

| 内层序列 | 内层日程 | 初始模型 F1 | 原两轮模型 F1 | 外层差值（百分点） |
| --- | --- | --- | --- | --- |
| 整段 | 常数（原设置） | 31.23% | 28.64% | −2.59 |
| 整段 | 线性衰减 | 42.69% | 40.26% | −2.43 |
| 按行 | 常数 | 13.04% | 12.80% | −0.24 |
| 按行 | 线性衰减 | 17.70% | 33.09% | +15.39 |

两次“整段 + 常数”重跑与原始预测逐题一致，排除了读错模型或未重复到原测量的解释。
固定初始模型与整段输入，只将学习率改为线性衰减，F1 增加 11.45 个百分点：
**内层优化日程确实影响了原结果，不是仅在配置表中发现一个无关差异。**
按行也会增加优化器更新次数；这里测的是论文构造方式的整体影响，不能进一步称为
排除了步数的纯分段效应。

“按行 + 线性”的正差值说明结果对内层协议敏感，但并未证明完整 SEAL 收益：
原外层模型仍是在旧奖励过程上训练的；只有一个训练种子；改动是在已看过结果的
验证集上作诊断。按文档成组重采样 20,000 次，其 F1 差值 95% percentile 区间约为
**[−1.51, +32.52] 个百分点**，仍跨零。该区间只描述这 8 篇文档的重采样，
不包含重新训练和生成 self-edit 的随机性。

原设置 −2.59 点的同类区间为 [−11.67, +8.31]；EM 为 7→7，其中 2 题变对、2 题变错。
因此原始测量也不能证明稳定退化。

原记录中，不做内层适配时初始/两轮模型的 F1 分别为 37.56%/37.07%，
均高于原设置适配后的 31.23%/28.64%。这提示应先验证内层适配是否有效，
再判断外层是否学会生成更好的 self-edit；此前没有充分检查这项基线。

此外，优化器 weight decay、EOS/padding 和完整内层 Trainer 的行为仍未全部对齐。
本次线性对照保留原 AdamW 的 weight decay，不冒充完整上游 Trainer。

### 上游也存在需澄清的脚本歧义

固定版本的 [query_server.sh][seal-query] 设置 `SPLIT_NEWLINES=1`，
却只在值为字符串 `true` 时传 `--split_newlines`，所以按该脚本实际不会启用按行拆分。
这与论文描述有差异，需要明确采用论文协议还是该脚本的实际行为。
这是可定位的上游复现入口问题，**不证明论文实验或收益造假**；
我们此前没有识别并记录这项冲突，是本地复现审查遗漏。

## TTRL：排除了最终评分解释，尚未完成训练对齐

### 关键协议差异

| 项目 | 论文 v3 / 固定上游实现 | 原 v1 实跑 |
| --- | --- | --- |
| 训练后端 | [固定上游配方][ttrl-recipe]的全参数 verl/FSDP | 独立 rank-32 LoRA 参考实现 |
| MATH 适配题数 / epochs | 500 / 10 | 32 / 2 次 on-policy 刷新 |
| 每题投票 / 训练响应 | 64 / 前 32 条 | 16 / 全 16 条 |
| 训练响应预算 | 名义约 160,000 条，未扣 drop-last | 1,024 条，名义预算的 0.64% |
| 学习率 | cosine，峰值 5e-7；脚本另设 warmup | 常数 5e-7 |
| loss aggregation | 固定上游默认 token-mean | sequence-mean |
| 训练 rollout top-p / 最大输出 | 默认 1.0 / 3072 | 0.95 / 2048 |
| 主表评测 | 每题 16 次采样，T=0.6、top-p=0.95，平均正确率 | 每题一次 greedy |

“128 个优化器步”不等于复现了官方训练量，因为有效 batch、参数化、
响应总数与 on-policy 刷新频率都不同。64 票与 16 票也不是同一种奖励信噪比。
独立迁移集是额外诊断，不应拿其变化替代论文的适配集合收益。

### 官方判分器重算

在相同的已保存回答上运行固定版本的完整数学 reward 包，
得到的最终结果与本地 verifier **完全一致**：

| 数据 | 本地判分，初始→最终 | 官方判分，初始→最终 |
| --- | --- | --- |
| 32 道目标题 | 23→23 | 23→23 |
| 128 道迁移题 | 92→88 | 92→88 |

目标题逐题正确性也全部不变。迁移题为 2 题变对、6 题变错；
配对二项 McNemar exact 双侧 p=0.289，单次小样本不能证明稳定退化。

但这只排除了最终判分造成表中差值的解释，不证明奖励实现等价。
在每轮 512 条同一 rollout 上，官方投票/奖励路径与本地实现分别有
**36、37 条奖励不同**，标准化/表达式分组差异仍需单独验收。

### 标签只用于离线诊断的奖励审计

| 观测 | 第一轮 | 第二轮 |
| --- | --- | --- |
| 多数伪标签正确的题数（本地 verifier） | 23/32 | 26/32 |
| 有非零优势的错误多数题 | 9 | 6 |
| 错解被正奖励的响应 | 51/512 | 37/512 |
| 正解未被奖励的响应 | 24/512 | 10/512 |
| 全组零优势的题 | 8 | 9 |
| 输出达到长度上限 | 17/512 | 12/512 |

这证实训练信号确实含噪，部分题在强化错误多数，部分题没有策略梯度信号。
它们是 TTRL 所承认的风险，不能单独证明本次失败原因；需要用同一算法的官方
64 票协议对照，才能测量缩减投票预算带来的影响。
长度截断存在，但占比仅约 2–3%，没有依据把全部差距归给输出预算。

原训练记录显示平均 token ratio 偏离 1 约 0.005、sample KL 约 0.00029，
发布后的权重也确有变化。结合有限预算，它们支持“做了幅度较小的更新”的解释，
不能据此认定 LoRA 是唯一原因。当前没有完成全参数与 LoRA 的受控重训。

## 什么结果才允许进一步归因到论文

1. 固定目标论文版本、官方源码、模型/数据 revision、训练及评测协议，先对齐初始基线。
2. SEAL 补足 50×5×3 的 E-step、外层有效 batch/rank/日程和语义判分；
   先验证一次内层样本更新与上游一致，再重训外层并在完整独立评估集验收。
3. TTRL 将官方后端接入 Lab 的 engine 边界，对齐 token-mean、优化日程、
   64→32 采样、完整 MATH 适配和 16-sample 评估；用共享 rollout 比较单步 loss/梯度/更新，
   随后比较完整日程。保持同一 controller，不让 host 按标签分数代选 checkpoint。
4. 在多种子、完整预算下仍无法得到论文所述趋势，再将剩余差异收敛为具体的上游问题。
   当前还没有到这一证据门槛。

这项分析没有把诊断中表现最好的组合设为新默认，也没有修补原始 run。
正式参考后端的修正和完整数值复现仍是下一项独立工作，不能用诊断报告替代。
