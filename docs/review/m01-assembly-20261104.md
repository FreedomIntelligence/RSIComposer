## 当前默认与选择

| 组件 | 默认行为 | 替换或关闭 |
| --- | --- | --- |
| context/memory | 必须激活；Journal 提供事实记录与工作视图，无额外模型推理 | LangMem 或外部 organizer/processor；None 拒绝 |
| 轨迹产物 | JournalTrajectoryArchive，提取公开片段 | 可替换，None 关闭派生产物；原始执行 journal 保留 |
| harness 提案 | 关闭 | 显式提供 ModelHarnessProposer 或其他 processor；正式 decision 负责构建/验证 |
| 模型/训练准入 | 宿主拥有 | 本次未取消、重置或转交模型管理 |

轨迹仍标记 complete_conversation=false、training_ready=false；提案不代表已应用改进。

## 统一入口的接线

- `Application(config, research=assembly, research_backend=..., feedback_adapter_factory=...)`。
- `build_demo(config, research=assembly, research_backend=..., feedback_adapter_factory=...)`。
- 医疗控制器完成 domain harness 构造后调用同一 assemble_research；所有新医疗任务均有 memory。
- 现有 examples/components/feedback_pipeline.py 同样使用统一入口。

Application/Demo 未传 research 时仍是底层循环构建器，保留既有组件测试与扩展组合能力。
旧 enable_* 和 feedback_learning_decision_factory 保留给兼容接入，不自动迁移冻结 run。
这次没有把 Runner 改成跨 Lab 调度器。

```python
from rsisys.application import Application
from rsisys.research import ResearchAssembly

# 默认事实整理与轨迹提取，不额外调用模型。
with Application(config, research=ResearchAssembly()) as app:
    app.run()
```

LangMem 用 `ResearchAssembly.langmem(memory_path=..., namespace=..., memory_options=...)` 选择；
其 provider 与 processor 配对安装，经同一 FeedbackPipeline 执行。缺少 optional 依赖或
native tool calling 时明确失败，不静默回退。配置对象不创建数据库/工作区，存储在首次访问时初始化。
手动 assemble_research 可用 owner 注册关闭；Application/Demo 自动登记，关闭不重复执行推理。

## 医疗参数迁移

- 默认 journal memory、轨迹提取开启、harness 提案关闭。
- `--memory-provider langmem`：选择开源 memory 管理器，要求独立且支持 native tools 的反馈后端。
- `--harness-proposals`：独立启用提案生成；仍经共享医疗宿主计费与日志。
- `--no-trajectory-archive`：关闭派生轨迹，不关闭 memory 或执行事实记录。
- 旧 `--feedback-learning`：选择 LangMem 的兼容开关，显式 --memory-provider 优先。
  新医疗任务不再调用旧的 memory/training_data/harness_change/system_change 组合解释 prompt。

project_context 明确区分 context_memory_enabled、memory_provider、model_feedback_enabled
和 trajectory_archive_enabled。只有真实调用计入 attempted，不把启用事实 memory 算作模型整理调用。
反馈模型身份不符、非法 provider/开关和缺少 native tools 在可知身份/能力的最早边界拒绝。

## 配置和恢复边界

有运行目录时，即使尚无回执，也保存 research_assembly.json 与 feedback journal 内的 assembly。
组件类型、声明配置、processor 配置与宿主限制参与重开检查；重复安装或配置冲突拒绝。
外部组件未提供 configuration() 时仅记录类型，外部状态仍需集成方显式恢复。
旧 journal 不自动迁移，恢复时不能遗漏原研究装配。

完整 Application durable 仍要求显式 recovery_contract；内置 snapshot 明确拒绝反馈服务。
上述配置检查和 journal 恢复不等于已经实现跨 Lab 任务恢复、自动重放或通用组件序列化。
