# Research 能力改进、反思与 Memory 的组件设计

2026-11-07。本次修订基于医疗实验的真实失败轨迹；代码改动在本地，未启动新研究窗口。

## 选择：统一的 Lab 执行能力，明确的改进对象

保留一个负责研究决策、Memory 和版本启用的 meta-agent。将研究能力改进表示为
目标为 `meta.harness` / `meta.prompts` 的研究任务，复用 Lab 的程序执行、产物、
作业和反馈协议。医学模型改进的目标是 Lab 内的候选模型；执行地点与改进对象分别记录。
当前已有程序异步执行能力，反思不再移除构建、测试、轮询和产物导出工具。

不复制完整医学 Lab 来创建第二份 controller、评测账本或 Memory。仅在需要独立权限、
工作区或资源配额时，装配一个隔离的能力改进执行环境。两个环境兑现同一 Lab 协议，
不用维护两套 RSI 主循环。

当前激活端口只支持 prompt 模板和已声明的 harness 参数；放开工具不意味着任意新 Python
harness 实现可以直接热替换。替换整套实现需要显式激活端口、恢复适配器和相应验收。

## 本次实现：有时间边界的反思会话

- `reflect_begin` 是普通、有账本的工具操作。它持久化开始时间、最长 3600 秒的截止时间，
  以及本次证据快照。上下文投影本身不写状态、不启动计时。
- 不限制反思操作次数，不在第 8 或第 16 步关闭修改工具。完整保留宿主实际授权且当前
  阶段可用的能力；只限制完成报告必须有完整原文证据。
- 证据范围覆盖上次完成反思之后的全部失败和最近一条原生操作。分页大小是输入窗口大小，
  不是总阅读量上限。开始后的新结果留给后续快照，避免完成条件不断移动。
- 截止时间取会话一小时和全局实验截止的较早者。重复 begin、恢复及跨半小时周期不续时。
  超时显示未完成；下一原始 cadence 才能显式继续待办。未完成不能成为 no_change 回执。
- 时间限制在决策准入和报告边界校验；已经发出的模型 HTTP 请求不会因此获得一个新实现的
  服务端强制取消机制。晚到的决策拒绝执行；Lab 子任务仍受其自身 timeout 和宿主总截止约束。
  真正的进程硬截止仍由宿主 supervisor 负责，不能将此调度计时宣称为推理服务抢占。
- 反思报告保存真实激活版本与证据，不把自评、候选构建或通过协议校验记为研究能力提升。

新增配置 `reflect_max_seconds` 默认 3600，允许 1..3600。恢复身份包含时限和全局截止；
旧运行不能静默装入新组件。旧冻结实验保持不变，代码变化需要显式 continuation。

## 本次实现：Memory 的显式处理阶段

Memory 是存储与检索组件，语义判断由当前 meta-agent 完成。通用装配通过
`ResearchAssembly.single_meta(require_memory_review=True)` 开启处理阶段；当前医疗 Open Lab
默认启用。其他既有入口保留 advisory 模式，仍提供待处理列表和处置工具但不改变其行动协议。
该配置进入装配身份，运行中不能暗改。

1. 新的 producer 结果进入独立待处理列表，不依赖已经打开的 research_task。
   包括实验结果、终态作业和真实失败；文件读取成功不作为学习成果。
2. 下一轮新实验前，先允许读取证据、检索笔记、管理任务和完成已有作业。
   agent 可以写入/更新来源明确的记忆，也可以执行 `memory_review`。
3. `memory_review` 必须引用存在的原始来源并写明理由：`already_known` 还要引用已有笔记；
   `deferred` 说明缺失证据与下一步；`not_useful` 说明为什么没有可复用结论。
   这是明确处置，不是宿主替模型编造经验，也不强制笔记数量。
4. 写入及处置进入同一修订账本，重启不能重置。重复交付同一结果不会不断制造新待办；
   同一作业产生不同结果仍需处理。导入历史本身不自动产生新工作，新 attempt 的新结果不会
   被同内容的历史笔记自动标成已处理。
5. 检索仍使用目标、当前反馈和任务的词面相关性及近期性。`memory_health` 分别公开待处理量、
   已处理量、笔记量、处置类型与显式 search/read 调用；不把展示预览或调用 read 自动判为使用有效。

跨 attempt 已可传输笔记、来源和任务。空库不能被传输机制变成知识；本修订补上产生和处理知识
的工作阶段。已有知识是否真正指导下一次行动，仍需从模型原始 decision reasoning、读取的
笔记版本、相关证据和后续执行核验。当前没有声称已完成自动因果归因。

## 后续并行扩展：一个提交者，多个隔离执行任务

建议增加可选 `ResearchJob` 执行器，而不是让两个 meta-agent 并发改同一 harness：

| 边界 | 约束 |
| --- | --- |
| 输入 | 不可变的目标版本、允许读的轨迹快照、任务目标、资源和绝对截止 |
| 执行 | 独立工作区、临时 Memory overlay、独立作业身份；可含同模型的独立推理上下文 |
| 返回 | 产物 SHA、父版本、代码/配置差异、测试与反例、实际计费、可选记忆提案 |
| 合入 | 主 meta-agent 读取原始结果；host 检查父版本，过期候选要求重验 |
| 写主状态 | Memory 修订和 system_activate 由单一提交者执行；子任务没有直接写权限 |
| 生命周期 | 同一总截止、调用账本和资源所有权；未知外部效果保留待核对，不自动重放 |

当前 `AccountedModelBackend._generate` 在同一对象上持锁覆盖 provider 调用，
`ModelDecisionPolicy` 也包含上下文和用量记录的可变状态。不能把它们直接同时从两个线程调用。
并行改造应将独立执行上下文与共享原子计费分开，验证预留、并发追加日志、取消、超时、重启
和乱序返回后再开放并发。现有多个客户端的调用号文件锁不等于整个并发执行器已验收。

模型服务部署与逻辑任务并发独立选择。先对同一服务承接两个真实工作负载做压测，记录总吞吐、
长上下文延迟、显存和排队；再比较两个服务副本。只有两种配置的实际证据才能决定部署方式。
200k 上下文、模型副本和 Lab 资源的取舍必须按实际硬件测试。本次未部署第二服务或并行 agent。

## 验收应回答的问题

首先证明能从真实失败读齐原文、编写候选、运行测试、保存产物并产生准确的 changed/no_change
或 incomplete 回执。随后比较相同冻结任务上的完成率、重复错误率、调用/时间成本和 Memory
引用后的行动变化。模型任务准确率与研究能力提升分开报告；只训练了 LoRA 不能证明 harness
改进，Memory 非空也不能证明有用。

离线 fixture 验证协议与恢复边界。真实 agent 是否主动选用、记忆是否正确以及能力是否改善，
仍需新的授权运行和相应对照证据。
