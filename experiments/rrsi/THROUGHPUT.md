# 2026-11-08：八卡 Lab 吞吐实测

同一台八卡 B200 服务器（`nvidia-smi` 枚举为 NVIDIA B20Z），同一份固定 Qwen3.5-9B，
8 个单卡 vLLM 0.32.0 副本。固定初始 harness，128 道相同留出题各 4 次采样，
每个有效运行均实际完成 512 次模型调用。压测不调用 RSI 决策器。

模型、精度、问题、请求 seed、temperature=0.7、top_p=0.95、关闭 thinking 及
max_tokens=2048 保持一致。没有缩短答案或提高失败容忍度。
总耗时包含隔离执行、模型生成与答案评分，不包含服务启动和图编译。
动态批处理的逐 token 输出并不完全相同，因此同时报告实际输出 token 吞吐。

| 配置 | 总耗时 | 输出 token/s | 逐卡平均 GPU 利用率范围 | 执行错误 |
| --- | ---: | ---: | ---: | ---: |
| 64 并发，eager，整批生成后评分 | 292.36s | 1874 | 27%–29% | 0 |
| 256 并发，eager，流水线评分 | 110.07s | 5024 | 28%–30% | 0 |
| 256 并发，CUDA Graph，流水线评分 | 23.22s | 23627 | 55%–70% | 0 |
| 256 并发，CUDA Graph，沙箱限流 | 19.85s | 27698 | 79%–91% | 0 |
| 512 并发，CUDA Graph，沙箱限流，重复 A | 17.01s | 31899 | 79%–90% | 0 |
| 512 并发，CUDA Graph，沙箱限流，重复 B | 15.57s | 35149 | 77%–85% | 0 |

基线共生成 547793 token；两个最终重复分别生成 542701 / 547435 token。
有效运行的解题准确率在 78.91%–80.27% 之间；本压测不用于判断 RSI 能力提升。
CPU 评分使用 16 个独立 spawn 进程，每个进程在主线程执行 Math-Verify，保留信号超时。
自定义 verifier 保留主进程主线程执行方式。输出轨迹和 rewards 按原题目及 trial 顺序交付。

有一组未限流的 512 并发运行产生 154 个沙箱启动超时，只执行了 358 次模型调用。
这组的 14.89 秒是无效吞吐成绩，未计入上表及提速结论；原始错误记录完整保留。
修复是将 HTTP 在途任务数与沙箱进程数分开管理：最多 512 个解题任务，
同时启动的隔离进程最多 32 个。候选实际执行的 5 秒墙钟限制、CPU 和内存限制均未放宽。

最终配方为 `workers=512`、`sandbox_workers=32`、`grading_workers=16`；
每卡 `max_num_seqs=128`、`max_num_batched_tokens=32768`，开启默认编译和 CUDA Graph。
生成与评分并行，减少尾部等待。本次测试是固定负载、预热服务的单机微基准，
不是对所有 harness、模型和输入长度的性能保证；搜索和 meta 推理的实际并行度取决于待执行任务数。
