# Independent medical assembly

This example composes `DefaultDecisionHarness`, `DefaultExplorationHarness`, and
`Runner`. Its normal policy is `ModelDecisionPolicy` with three bounded validation
attempts (generation/parsing only, before effects); research choices are not a
scripted production plan. The GPU entry below adds resource control around this
same assembly. The tests use scripted HTTP
responses and training receipts **only for integration verification**. Synthetic
symbol questions are not medical quality evidence. No source datasets are shipped.

Use Python 3.12+ from the RSISys directory with `PYTHONPATH=src:.`.

## Local format and read-only preparation

The example owns this UTF-8 JSONL schema, with exactly these fields per line:

```json
{"id":"unique-source-id","benchmark_id":"medqa","question":"<user-provided question>","options":{"A":"<option>","B":"<option>","C":"<option>","D":"<option>"},"gold":"A"}
```

IDs must be unique within a file and across development files. MedXpertQA uses
`medxpertqa` and A–J; MedQA `medqa` and MedMCQA `medmcqa` use A–D. PubMedQA
`pubmedqa` uses `yes/no/maybe` with `options: {}`. Its question contains the
question and permitted evidence context, without conclusion, long answer or gold
fields. Users must select legitimate labeled source splits, preserve source
versions/licenses, and convert their own native sources. In particular, do not
use MedMCQA hidden-test placeholder answers or confuse zero-based HF labels with
one-based source labels. The general JSONL reader does not infer those mappings;
the pinned converter below handles only its explicitly supported sources.

A local task JSON references train and development files relative to itself:

```json
{
  "train": "/absolute/user/train.jsonl",
  "development": [
    {"benchmark_id":"medxpertqa","role":"primary","path":"/absolute/user/primary.jsonl"},
    {"benchmark_id":"medqa","role":"guardrail","path":"/absolute/user/guardrail.jsonl"}
  ],
  "selection_rule": "pareto",
  "guardrails": true,
  "max_guardrail_drop": 0.02,
  "max_output_tokens": 32
}
```

```bash
PYTHONPATH=src:. python3.12 -m examples.medical.run prepare --config /absolute/task.json
PYTHONPATH=src:. python3.12 -m examples.medical.run check --config /absolute/task.json
```

Both commands read, validate and print the SHA256-bound frozen task; neither
writes files, downloads data, trains, calls models, nor starts a service. Exactly
one development benchmark is primary. There is no final/holdout configuration in
this researcher-facing task. Unknown fields are rejected.

`MedicalTask` and nested reference records are frozen. Each new measurement and
training preparation checks original bytes against their frozen digests. The
protocol identity covers the data refs, benchmark membership, output limit and
acceptance settings. Exact grading trims outer whitespace only: explanations,
prefixes, lowercase multiple-choice labels and altered PubMedQA capitalization
score wrong. `score` is primary accuracy; per-benchmark accuracy, macro F1 over
all legal labels and invalid-format counts remain separate. No aggregate accuracy
mixes benchmarks.

## Prepare cached benchmarks

`prepare_benchmarks` reads three existing cache files; it never downloads or
modifies sources. Unlike the read-only `run prepare/check` commands above, it
writes new output directories:

```bash
PYTHONPATH=src:. python3.12 -m examples.medical.prepare_benchmarks \
  --run-id medical-multiround-20261101T063200Z \
  --source-root /absolute/runroot/source-cache \
  --output /absolute/runroot/data \
  --private-output /absolute/runroot/operator-private \
  --train-count 1024 --dev-count 128 --guardrail-count 64
```

The cache layout and required source SHA256 values are declared in
[SOURCES](prepare_benchmarks.py). MedQA uses
`GBaker/MedQA-USMLE-4-options@0fb93dd23a7339b6dcd27e241cb9b5eca62d4d18`:
only `phrases_no_exclude_train.jsonl` supplies SFT rows; its test supplies the
64-row guardrail. The 128-row primary comes from
`TsinghuaC3I/MedXpertQA@7e7c465a68eb2b866926bfa59c8c9d17a8daba65`,
`Text/test.jsonl` (cached as `Text-test.jsonl`). Official Text/dev has only five
examples. Both evaluation subsets are **custom development partitions of test**,
not official dev, a new/fresh holdout, or a full-benchmark score.

Defaults freeze 1024/128/64 rows with seed 20261101; `--train-count 512` is also
supported without changing evaluation membership. Conversion preserves complete
clinical stems and legal option labels, removes only verified duplicate embedded
choices, and quarantines conflicting source rows. Exact question/ID dedup protects
the entire evaluation source pools before selecting train. It does not establish
semantic separation or absence of pretraining contamination; no medical content or
labels are generated by this script.

`data/` contains three domain JSONL files, `task.json`, `frozen_task.json`, and
`hashmanifest.json` binding source versions/hashes, conversion implementation,
selection and output bytes. Prepare at the final absolute path: frozen task
identity includes paths. The output directories must be new and disjoint from
each other and the cache. Remaining evaluation rows, lineage and quarantine audit
stay in `operator-private/`. Neither that directory nor `source-cache/` belongs in
model context or researcher artifacts. Optional `--exclude` reads operator-owned
domain JSONL exclusion lists without publishing their membership.

## Autonomous experiment

The [experiment entry](experiment.py) assembles the existing harnesses with
[transformers_runtime.py](transformers_runtime.py) for local inference and native
LoRA SFT by default. Run inside an explicitly allocated GPU job, with the intended
device mapped by its launcher, a cached official model, and compatible PyTorch,
Transformers, PEFT and training dependencies already installed:

```bash
PYTHONPATH=src:. python3.12 -m examples.medical.experiment \
  --task /absolute/runroot/data/task.json \
  --run-dir /absolute/runroot \
  --model-path /absolute/cached/Qwen3.5-9B \
  --seconds 5400 --max-trainings 3 --max-model-calls 96 \
  --max-seq-length 2048 --max-train-steps 64
```

There is no subcommand or separate backend/settings/recipe JSON for this entry.
The optional DSH harness takes an explicit session/provider JSON as described below.
For a single node with eight GPUs, select `--serving-backend sglang
--tensor-parallel-size 8 --training-processes 8`. The optional
[SGLang runtime](sglang_runtime.py) handles inference tensor parallelism;
the native Trainer uses eight data-parallel replicas for SFT. The assembly releases
inference resources before training and prepares the actual returned adapter for
candidate evaluation. Both frameworks remain outside the Harness. Each training
GPU must fit a complete model replica. `parallelism.json` records requested
parallelism; worker evidence records the ranks that actually trained.
Use `--seconds 1800` for a 30-minute research limit. The CLI arms its hard deadline
after baseline evaluation, excluding initial model preparation; the job launcher
must also bound startup time and guarantee resource cleanup.
Add `--run-mode time --seconds 1800 --max-model-calls 10000` for continuous
30-minute research. This selects the existing `TimeRunPolicy`: researcher finish
ends a cycle, then restarts after `--restart-delay-seconds` (default 10), retaining
history, candidates, incumbent, training reservations and model-call counts.
It does not require a particular experiment. Time mode has the same hard deadline;
model-call and training caps remain cumulative, so choose a sufficiently high
call allowance when the clock should be the effective stop condition.
`run_control` reports live remaining time, training slots and model calls each
decision; `researcher_finish_ends_run` is false in time mode. The default
`--run-mode researcher` still allows an early finish.
Optional repeated `--private-exclusions /operator/excluded.jsonl` supplies domain
JSONL rows solely for trusted overlap checks; their contents stay out of public
research context.

The medical policy uses `MemoryPrefixDecisionPolicy`: user context starts with the
objective, versioned `project_context`, live capabilities and memory. Project scope
covers target/exploration and decision improvement, frozen scientific evaluation,
data restrictions and budgets; the same context is saved as `project-context.json`
for review. Live operations/directives and executor permissions
authorize execution. Harness/system changes and decision-model training remain
proposals unless an executable capability is installed. Learned memory remains
untrusted user content.

`ExperimentSettings.resource_allocation` defaults to `None` (unknown). Device type
and training process count describe configured execution; neither host visibility
nor environment variables establish allocation or free memory. Supply only an
operator declaration, for example `resource_allocation={'physical_devices': [13],
'logical_devices': [0]}` with `training_device_type='npu'`. The CLI equivalent is
`--resource-allocation '{"physical_devices":[13],"logical_devices":[0]}'`.
Physical/logical IDs appear only when declared; no physical-to-logical mapping is
inferred. Optional `memory_availability` is an explicit string/object declaration;
otherwise it is unknown. Optional `external_read_only_services` is a list of JSON
objects describing already available services; it grants no training, adapter
loading, restart or reconfiguration rights. The allocation is copied and bounded
to 8192 JSON bytes, depth 8 and 512 values; other top-level fields are rejected.

Feedback learning is disabled by default (`feedback_learning=False`). Enable it
with `ExperimentSettings(..., feedback_learning=True)` or `--feedback-learning`.
The default harness requires an independent `decision_backend` or `feedback_backend`;
DSH can use isolated feedback sessions with the same runtime configuration, or an
explicit `feedback_backend`. Optional `feedback_model` selects its model identity.
Custom harness factories also supply `feedback_adapter_factory` for their evidence
and publication contract; they need not subclass the default harness.

The feedback service preserves the chosen harness, policy and compactor. It installs
`feedback_learning_read` through the built-in ledger adapter and journals unverified
proposals; it does not train or apply changes. Both decision and feedback transports
pass through the same serialized admission gate, output recovery and model-call budget.
Feedback never reuses the DSH decision session cursor. Inference during training is
rejected; worker monitor events are queued for the controller and flushed at shutdown.

The Transformers backend stops researcher generation after one complete final JSON object (the policy still
checks the action schema and permissions). Reasoning and incomplete JSON cannot
trigger an action. Actor evaluation has no JSON stopping rule.
SGLang uses native generation; its final response passes the same policy parser
and permissions. It does not silently select one action from a multi-action response.
`--decision-max-output-tokens` sets the researcher output ceiling (default 8192),
independently of thinking mode. Smaller feedback-learning or compaction request
budgets are preserved; a declared native backend ceiling also remains binding.
Actor answer-length limits are unchanged.
`--decision-response-retries` allows 0–2 additional calls (default 2) for explicit
response truncation/JSON format failures. Each call consumes the original shared
model-call budget and rechecks the research deadline; identity/revision mismatches,
refusals and transport failures are not retried. Recovery retains the same schema
and output ceiling and never executes partial output. Canonical decision validation
still runs before execution. For vLLM, `model_wire_responses.jsonl` persists the bounded
HTTP response body before parsing; `model_response_errors.jsonl` records the call,
reason, finish reason and retryability. Failure to save wire evidence aborts the call.
These files are operator evidence, not additional input to the decision model.
Optional `--decision-thinking` enables the Qwen researcher thinking template and
sampling (temperature 0.6, top-p 0.95, top-k 20).
Only the final answer after the reasoning delimiter reaches the decision parser;
incomplete reasoning is rejected. Token usage includes reasoning. Actor scoring
and completion-only SFT remain non-thinking, with greedy actor inference.
The default policy retains complete context below 80,000 input tokens, then
summarizes older records toward a complete request budget of 24,000 tokens.
It protects the latest tool receipt, two newest history records and current
feedback in full; an oversized protected request fails rather than cutting that
feedback. A native tokenizer is used when available; otherwise the count is
explicitly a conservative UTF-8 estimate. Full archives remain readable. The
medical policy adds no 600-character summary, field allowlist or 8k character limit.
It uses **LoRA SFT, not full-parameter training or RL**. The researcher chooses
data subsets, bounded recipes, prompt experiments, evaluation and application;
there is no fixed three-round research script. Defaults allow 90 minutes of
research after the separately recorded baseline, at most three SFT submissions
and 96 decision-model calls. The researcher may choose `finish` with a reason at
any time. These are upper bounds: the run need not last
90 minutes, use all calls, or complete three training rounds. Exhausting training allowance disables further training
while other permitted research actions can continue. Recipe steps are bounded by
`--max-train-steps`; the default recipe uses 32 steps, learning rate 1e-4,
microbatch 1 and gradient accumulation 2.
`define_recipe` shares its parameter types, bounds and defaults with native recipe
validation: steps 1..`--max-train-steps` (default min(32, cap)), learning rate
1e-6..1e-3 (default 1e-4), integer seed 0..2^31-1 (default 0), weight decay
0..0.1 and warmup ratio 0..0.2 (both default 0). Invalid parameters are rejected
before a recipe is created. `preview_training_data` defaults to offset 0 and
limit 8; `choose_training_data` requires either 1..4096 unique string IDs or
both offset and limit (1..256). The two selection forms cannot be mixed.
Offsets range from 0 through the effective training row count; selecting an
empty page returns a failed operation receipt. `prepare_data` accepts 1..65536
characters and then checks JSONL content, protected overlap and token length.
`read_artifact` requires a nonempty visible artifact ID; training artifacts return
summaries and references, while source row previews remain paginated.

The research objective is to improve both MedXpertQA and MedQA performance.
The researcher chooses data, SFT recipes, inference prompts or combinations;
no particular method or training submission is required. It chooses its plan
and can finish with a reason within the externally defined capabilities and budget.

### Replace the decision harness with DSH

`--decision-harness default` remains the default. Select `dsh` to replace the
whole decision harness with `DeepSeekDecisionHarness`, including its persistent
native session, asynchronous lifecycle and native compaction. Both choices use
the same medical operation/directive registrations, execution-time permissions,
training allowance, external run policy, actor, evaluator, candidates and evidence
store. `ResearchPolicy` supplies medical JSON parsing/validation to either harness;
DSH owns generation and context management. Both its parser and outer harness use
`IdentityContextCompactor`, so there is no second Basic compaction layer.

Install the pinned optional SDK in an isolated environment, outside model serving
or training environments, after reading the [official SDK instructions](https://github.com/deepseek-ai/deepseek-harness/blob/master/python/sdk/README.md).
For the existing Qwen/vLLM Chat Completions endpoint, use an absolute JSON path:

```json
{
  "home": "/absolute/isolated/dsh-medical-home",
  "workspace": "/absolute/medical-workspace",
  "model": "Qwen3.8-27B",
  "session_id": "medical-independent-comparison-001",
  "provider": "openai-completions",
  "base_url": "http://127.0.0.1:8000/v1",
  "api_key_env": "RESEARCHER_API_KEY",
  "context_window": 131072,
  "max_tokens": 2048,
  "trigger_tokens": 80000,
  "target_tokens": 24000,
  "summary_tokens": 4096
}
```

Provide the endpoint credential through the named environment variable; keyless
local endpoints may accept an explicit placeholder. `base_url` must name the API
root, not `/chat/completions`. The declared capacity must match the serving model.
Each comparison uses a fresh native session and a fresh experiment run directory;
this experiment entry rejects `resume=true` and never launches a run automatically.
Add these flags to the ordinary explicitly launched experiment command:

```bash
--decision-harness dsh --dsh-config /absolute/dsh-medical.json
```

Fixed SDK `0.2.1rc2`'s `deepseek-official` route uses `/v1/messages`; a base URL
override does **not** make it compatible with Qwen's `/v1/chat/completions`. The
explicit `openai-completions` option mounts the bundled `llm-pi-ai` plugin and
registers `rsisys-local`, with native retries disabled. Plugin/configuration errors
fail visibly; there is no provider fallback. This route has been checked with the
real pinned SDK/runtime, persistent-session resume and automatic compaction against
a deterministic loopback SSE server. The same pinned SDK also completed two
synthetic read-only turns against the existing `Qwen3.8-27B` vLLM endpoint through
this route, with provider-reported input/output usage of 229/101 and 404/52; the
second response retained the latest raw receipt marker. This verifies actual
provider access, not a real medical experiment or native 80k-to-24k compaction
against that model. The large native compaction test remains a fixture test.

DSH sends new complete tool receipts and new/changed archive records incrementally.
It reasserts the live JSON protocol, operation/directive schemas and run control
each turn so native summaries cannot erase the current permissions or syntax.
The fixed training input reference is published in run control; it is not appended
after each tool receipt. The native session retains older observations and the
transport cursor participates in DSH recovery.

DSH's 80k trigger uses the native meter. Its 24k **retention target** allocates
19,904 tokens to recent native history and caps the native summary at 4,096.
Fixed system/tool/session-prefix tokens and indivisible message boundaries are
outside that retention calculation. This is not the default harness's strict
preflight check of the complete request against 24k. After a native summary, if
the SDK supplies authoritative aggregate `totalTokens` and `outputTokens`, the
adapter checks their difference against 24k and withholds an oversized proposal
with `ContextBudgetError`; the native session has already advanced and requires
reconciliation. Without those counters, full-request validation remains explicitly
unknown. `dsh_context_budget.json` records that distinction. No tool receipt is
shortened by the RSISys transport to meet the target.

`max_model_calls` counts admitted native turns plus conservative reservations at
SDK `compaction/start` events, including attempts that may need no model call.
Waiting scheduler ticks consume no calls. Native notification delivery is not a
synchronous HTTP admission hook, so this count is not an exact internal-request
count and cannot recall an already dispatched inference. Full SDK events are
archived in `dsh_events.jsonl`; unknown turn-wide token usage stays unknown.
`decision_harness.json` records provider, budgets and counting mode.

Programmatic `run(..., dsh_runtime_factory=...)` injects a runtime for controlled
comparisons. `decision_harness_factory(**dependencies)` may replace construction;
dependencies include tools, experience, memory, agenda, directives, model,
`policy_factory(native_backend, model)`, budget backend, DSH config/runtime factory
and native notification callback. Preserve those dependencies to keep the same
capabilities and accounting. DSH uses its configured independent researcher;
`decision_backend` is reserved for the default harness and is rejected with DSH.
Neither choice requires training or a `finish` decision to consume the full budget.

The initial baseline is measured before research starts and its evidence is
readable through `read_artifact`. It is not a proposed candidate. Candidate
evaluation/application are exposed only once a candidate exists; this reflects
their input precondition without prescribing which research action creates it.
An empty candidate list still permits `configure_prompt` and `train` to create
new candidates, plus the available data, recipe and research-note operations.
Only evaluation and application require an existing registered candidate.
The medical assembly defaults an omitted `protocol_ref` to its frozen protocol.
It also resolves an omitted `candidate_id` only when exactly one candidate exists;
multiple candidates require an explicit model choice. Raw model output and the
resolved directive are recorded separately. Validation retries include the failed
proposal, error and available candidate IDs, without silently selecting an experiment.
Training inputs belong in top-level `input_ids`. Medical initialization is
host-owned: `origin` is absent from the model's schema, and the parser rejects
any supplied `arguments.origin`, including null. The executor binds the current
experimental parent and fixed initializer using restart without a checkpoint.
`apply_result` may be omitted or false; candidates require separate evaluation
and application. The parser enforces the advertised backend methods and any
fixed native recipe reference before execution.
The example policy resolves named actions (`action`, a named `kind`, or the
`invoke`/`explore` envelopes) only when the name uniquely identifies a currently
allowed operation or directive. Conflicting names are rejected.
Arguments are unchanged, original/normalized forms are logged, and normal permission
and schema checks still apply. Disabled or ambiguous names gain no access this way.

The frozen source selection is train/primary/guardrail **1024/128/64**. Before
training, the tokenizer checks complete chat-template sequences, including the
supervised answer, against the length limit. Overlong training rows are excluded
whole; retained rows go to `effective-train.jsonl`, with `data-manifest.json` audit
and a separately frozen `effective-task.json`. Original `data/` bytes stay frozen.
The effective task is a serialized frozen dataclass, not an input config for
`--task`. Effective train size can therefore be smaller than 1024. Development
membership stays fixed. Inputs and answers are not silently truncated.
For `medical-multiround-20261101T063200Z`, the operator's real-tokenizer preflight
retained all 1024 training rows (maximum complete sequence: 587 tokens). This is
preflight evidence only; actual training and inference outcomes are recorded in
the run's logs and result files.

Inference and training share the GPU **serially**. The serving runtime releases
its loaded model before native training and lazily reloads for later inference;
model calls must not reload inference while a training process holds the device.
The decider always uses the fixed baseline weights with actor adapters disabled.
Actor LoRA updates change candidate inference only; they do not update the
researcher. `tokenize_factory` exposes `filter_samples`, tokenizer/template
metadata and `conversion_id`; `LocalTransformerServing` supplies generation,
`prepare_inference`, activation and synchronous `release_memory`. See those
implementations for the full interfaces.

Keep source caches and `operator-private/` outside model context. Researcher reads
are restricted to registered artifacts; this entry does not grant filesystem
tools. Audit starts with `steps.jsonl`, `events.jsonl`, `model_responses.jsonl`,
`model_calls.json`, the memory/experience snapshots, `candidates.json` and
`evaluations.json`. `baseline.json` records the anchor; `artifacts/` retains raw
development predictions and acceptance evidence. Training recipes, budget and
cleanup live under `training/`; `model_identity.json` and
`serving-weight-identities.json` bind model identities. `monitor.json` reports
progress; `result.json` uses `completed` for model finish, `stopped` for budget or
interruption, and `failed` for errors. Evidence is not a claim of medical gain.

`controller-started.json` is created exclusively and blocks restarting the same
controller run directory. Use a fresh run after reconciling interrupted work.
Persisted native job receipts and research snapshots do **not** provide complete
process-crash resume of the runner, evaluator, registry, GPU state and external
effects. On interruption, reconcile this run's jobs and partial evidence before
starting again. Cleanup concerns this controller's jobs only; a hard kill can
bypass cleanup, so the launcher/operator still owns resource reconciliation.

## Explicit run

For a prompt-only run against already configured Chat Completions servers, supply
a backend JSON with `decision_binding`, `decision_model`, `actor_binding`, and
`initial_model`. Each binding follows `BackendBinding` (backend_id, kind, endpoint,
optional credential_env); model refs contain backend_id, model_id and revision.
Use `json_mode: false` on the actor binding for exact label answers. Credentials
are environment variable names, never secret values in files. Endpoint roots
include `/v1` when the server uses that prefix. No endpoint or model is guessed.

A settings JSON explicitly provides `objective`, `max_runner_steps`, and optionally
`poll_interval_seconds` (default 1). Then:

```bash
PYTHONPATH=src:. python3.12 -m examples.medical.run run \
  --config /absolute/task.json --backends /absolute/backends.json \
  --settings /absolute/settings.json --output-directory /absolute/new-run-artifacts
```

This starts baseline development inference, then lets the model choose tools and
directives. It reports `done` when the researcher/run policy finishes. Step-budget
exhaustion or baseline inference failure reports `needs_input` (CLI exit 2).
Pending jobs are not automatically cancelled. Polling sleeps while waiting.
A fresh CLI invocation creates a new in-memory assembly; it is **not** a resume
command. Use a new output directory, and reconcile pending work before another run.

Python is the native training/deployment injection entry:

```python
from examples.medical.run import build, RunSettings
from examples.medical.evaluation import MedicalEvaluator
from examples.medical.native import MedicalTrainingBackend, MedicalServing
from rsisys.adapters.serving import VLLMBackend, VLLMDeploymentBackend
from rsisys.runtime.artifacts import FileArtifactStore

artifacts = FileArtifactStore(output_directory)
candidate_backend = VLLMBackend(actor_binding)
deployments = VLLMDeploymentBackend(
    candidate_backend, deployment_directory,
    adapter_paths=operator_adapter_paths,
    allow_runtime_lora=runtime_lora_opt_in,
)
# For a new trained candidate, resolve the published native_model_manifest
# to an immutable path visible to the serving host. Return None for the baseline.
serving = MedicalServing(deployments, adapter_path=resolve_candidate_server_path)
native_learner = MedicalTrainingBackend(
    native_job_directory, artifacts,
    tokenize=tokenize_samples,
    conversion_id=tokenizer_revision_and_template_identity,
    recipe_template=native_recipe_template,
)
assembly = build(
    task, artifacts=artifacts,
    decision_backend=researcher_backend, decision_model=researcher_model,
    initial_model=expert_model,
    inference=serving,
    system_activator=serving,
    learner=native_learner,
    bind_training_inputs=native_learner.bind_inputs,
    training_initializer=expert_model,
    run_policy=explicit_run_policy,
    action_permissions=permissions,
    prepare_inference=serving.prepare_inference,
    evaluator_factory=MedicalEvaluator,  # Optional; this is the default.
    trusted_exclusions=operator_only_exclusion_rows,
)
result = assembly.run(RunSettings(objective="<explicit research objective>",
                                  max_runner_steps=100, poll_interval_seconds=1))
```

`build` writes immutable task/input artifacts but makes no model calls and starts
no jobs. The optional `evaluator_factory(task, artifacts, systems, candidates,
inference, *, prepare_inference=None)` receives the same explicit dependencies.
Its public contract consists of `task`, an `evidence` dictionary mapping visible
artifact IDs to managed refs, `establish_anchor()`, `measurement(candidate_id)`
(returning a copied EvaluationResult or None), `interpret(candidate_id)`,
`completed_evaluation(candidate_id)`, and the evaluator submit/poll/cancel/result
job methods. Application reads only these public evaluator interfaces.

`prepare_inference(system)` is an optional trusted serving-readiness hook, called
before baseline and each candidate's first evaluated sample. It must confirm the
actual requested model route, or raise `ModelActivationPending` while deployment
is pending/uncertain. The same frozen system is retried on later polls. A hook
that merely records a model name without checking the live route is insufficient.
The default evaluator scores at most **one sample per poll**. Pending preparation
returns RUNNING without querying a sample; completed rows remain accumulated and
are not repeated. Cancellation can take effect between requests and preserves
partial raw predictions. A single synchronous provider request is still bounded
by that provider's timeout, not interruptible mid-request.

`establish_anchor()` is intentionally an explicit synchronous baseline call. It
walks the baseline samples before autonomous decisions begin; it is not called by
prepare/check/build. If baseline serving is pending, `run` returns `needs_input`;
retain the same assembly and resume after readiness, without repeating already
scored baseline rows. The caller owns adapters, their device allocations and cleanup. Inference
is an explicit callable `GenerationRequest -> GenerationResponse`, or a
`ModelBackend` adapted with `backend_inference`. It must serve the **requested
candidate model**, including before application. Its sampling/server configuration
must be fixed by the operator; the generic GenerationRequest carries the frozen
output limit, not a portable provider sampling configuration. Candidate UTF-8
prompt instructions are prepended to the fixed legal-label instruction. Gold is
never in the inference request. Transport identity checks do not attest weight
contents unless the serving provider independently verifies them.

`system_activator.activate(SystemVersion, idempotency_key=...)` confirms the same
manifest when ready; use `ModelActivationPending` until readiness. Reference-only
activation supports prompt changes with an unchanged model. `SystemRegistry`
merges component candidates, enforces their explicit parent and applies via CAS.
A prompt proposal creates a candidate without mutating the incumbent. Evaluation
uses `EvaluationSpec`, so the default harness retains candidate evaluation context.
Application rechecks the frozen `selection_rule` against the current incumbent.
The default `pareto` rule requires at least one development benchmark accuracy to
strictly improve and none to decrease, including MedQA-only improvements. Ties
are not accepted. Tradeoff candidates retain their measurements, raw evidence and
registry entries for subsequent comparison, but cannot replace the incumbent.
The `score` primary metric remains a reporting convenience, not the Pareto selector.
`MedicalEvaluator(..., acceptance_policy=callable)` replaces the selector explicitly;
the callable receives `(task, candidate_measurement, incumbent_measurement)` and
returns a dictionary with boolean `accepted` and policy evidence.
The explicit legacy `selection_rule: "primary_guardrail"` requires primary improvement
and uses `guardrails`/`max_guardrail_drop` relative to the initial fixed anchor.
Those legacy tolerance fields do not relax the Pareto rule. The selection rule is
included in the frozen protocol hash; historical runs are not rewritten. A known candidate that
fails acceptance, has no successful evaluation, or has failed interpretation
receives FAILED application feedback plus a rejection artifact. The incumbent stays
unchanged and the researcher chooses its next action; rejection does not exit the
runner.

The configure_prompt, evaluate and apply_candidate directive specifications declare
`accepts_input_refs: false`. Omitted `input_ids` means empty for those modes;
explicit nonempty input IDs are a validation error before effects. Their backends
also reject unexpected input refs. Training alone consumes explicit data refs.

Activation pending remains a nonterminal `applying` receipt, and subsequent runner
ticks reconcile the same candidate and idempotency key. Cancellation before an
activation intent starts prevents activation. Once activation has been issued,
cancellation cannot discard an uncertain remote effect: the same receipt stays
pending until readiness is confirmed. If application is confirmed, feedback says
it completed despite the late cancellation, with `cancel_requested` and
`activation_confirmed` evidence. No rollback is claimed. `SystemActivationRejected` is converted to FAILED
application feedback only when the activator confirms that application did not
occur (or was rolled back). Unknown external errors still propagate with the
application intent/receipt retained.

Training requests always carry `TrainingOrigin`. Default restart initialization is
`training_initializer` (default the explicit baseline model), independent of the
current experimental parent. The medical executor accepts only this host-bound
origin: current parent, fixed initializer, restart and no checkpoint. Completed
training outputs enter `SystemRegistry.register_training(result, origin=...)`,
which checks the submitted initializer separately from the experiment parent.
After a LoRA incumbent is applied, a later experiment can still restart from the
original pinned model and inherit that incumbent's prompt/configuration. Its
candidate must be deployed and evaluated before application; the parent must
still be current and the configured acceptance rule must pass. This also
applies to programmatic directives. A declared backend must support restart;
other resume modes remain outside this medical assembly. The adapter must return the same
parent in its candidate; the example never adds a parent after training.

`bind_native_inputs(request, artifacts) -> ActorTrainingRequest` is **required when
a learner is supplied**. This trusted callback validates/materializes the actual
native recipe and training inputs against `request.data_refs`. It may replace
`recipe_ref` with the bound native config identity; data refs, base, method and
origin must remain identical. The native command must read that bound config,
consume precisely those validated source bytes (or their explicitly documented
conversion), and retain source digests, conversion/tokenizer identity and actual
consumption evidence. Do not validate one file while a preconfigured trainer reads
another. For `ProcessTrainingBackend`, inject a native `command(request, job_dir)`
that consumes this binding; its default tokenized-JSONL worker cannot consume this
example's question/options JSONL unchanged. No universal converter, dotted dynamic
imports or hidden source-data fallback is installed.

The bundled `MedicalTrainingBackend` keeps caller source refs/origin intact,
materializes its configured native recipe and tokenized input once per submission,
and records source digests/IDs, conversion identity, native recipe/data hashes and
native training evidence. `tokenize_samples(tuple[Sample, ...])` must return native
feature dictionaries with `input_ids` and `labels`; it is an explicitly supplied
operator conversion, not an automatic benchmark importer. Its fixed `recipe_ref`
is a template-content hash. `build` advertises that ref as the training schema's
single allowed recipe; the backend independently rejects other refs. Learners
without an explicit string `recipe_ref` retain the general recipe schema.

`MedicalServing` is both the inference callable and SystemActivator. Pass its
**`prepare_inference`** method as the evaluator hook. `VLLMDeploymentBackend`
checks the serving alias and probes it before candidate evaluation; adapter paths
must be explicitly mapped to the requested model. For dynamic candidates, the
optional `adapter_path(system)` callback may read the managed `model` manifest
(`native_ref` identifies the native output) and map it to a serving-host path.
This callback owns cross-host accessibility; the framework does not copy weights
or guess mount mappings. It cannot change an existing model-to-path binding.
Runtime LoRA mutation requires
explicit opt-in; static/shared routes are not restarted or replaced. The hook and
inference must use the same serving object/backend. Wrapper-level durable training
receipts do not make the example's in-memory loop state durable.

The trusted overlap validator excludes normalized, casefolded, whitespace-collapsed
question matches and IDs against all development samples and programmatically
supplied private exclusions, before training submission. Private exclusion rows do
not enter the task, model prompts, tools or experience. This is exact separation,
not semantic deduplication, pretraining contamination detection or medical fact
validation. The caller must keep private files/artifacts out of any researcher
workspace; this assembly installs no arbitrary filesystem tool.

## Evidence and lifecycle limits

Raw artifacts contain each actual development output, legal-format flag, grade,
model/prompt manifest and usage. Acceptance interpretations are separate artifacts
with raw source refs. `read_artifact` accesses only published train/prompt/development
evidence. External component references (including `file:///` weight directories)
return reference metadata and an explicit external-resolver requirement; the read
tool does not pass them to the artifact store or traverse directories.
ResearchTools shares the decision harness's memory and agenda; archived
observations and researcher notes retain their distinct roles. The installed action
catalog exposes only real data storage, visible artifact reads and research tools.

Malformed model/data results and transport failures become terminal evaluation
failures, with completed predictions retained as partial raw evidence.
Interpretation errors also terminate the evaluation as failed and preserve links to
its completed raw measurements. A failed interpretation cannot authorize application. No hidden
network retries or repeated queries occur when that failed job is polled again.
These partial observations are not a complete benchmark score. A new evaluation
implementation/assembly is required for an explicit retry after reconciling failure.

With `FileArtifactStore`, task manifests, predictions and interpretation artifacts
persist. Loop state, experience, evaluator receipts and SystemRegistry are currently
in memory. Retain the same assembly to resume a bounded Python run; process-crash
recovery requires caller-owned coordinated persistence. This example does not claim
durable evaluation or medical efficacy. Native backend/deployment proof is separate
from the explicitly labeled fixture verification:


## Run ancestry declaration

`python -m examples.medical.experiment` accepts
`--run-dir runs/run6 --parent-run-id run5` (Python:
`ExperimentSettings(..., parent_run_id='run5')`). This declares ancestry only.
The medical controller still starts a fresh assembly; it has no cross-process
continue/resume path and this flag restores no memory, model or optimizer state.
`run.json`, `monitor.json` and `result.json` retain the same source fields.

loads adapters into, stops, or reconfigures the external endpoint. Pin the actor
alias and endpoint to the declared base. HTTP aliases do not attest weight bytes;

New medical research leaves Attempt membership optional. Decisions still describe
concrete actions in `reason` / `strategy`, with executable parameters and inputs;
missing Attempt metadata does not block prompt, data, training or evaluation work.
